1. PROJECT OVERVIEW & NOVELTY
================================================================================

WHAT IS EDGE-LLM?
Edge-LLM is a framework that enables efficient large language model (LLM) 
adaptation on edge devices through three core innovations:

KEY INNOVATIONS & NOVELTIES:
─────────────────────────────────────────────────────────────────────────────

1. LAYER-WISE UNIFIED COMPRESSION (LUC)
   • Automatically generates layer-wise pruning sparsity policies
   • Generates layer-wise quantization bit-width policies
   • Uses MSE (Mean Squared Error) analysis per layer
   • Reduces computation overhead by 50% or more
   • Files: pruning/llama_pruning.py, quantization/quantizedlinear.py

2. ADAPTIVE LAYER TUNING & VOTING (ALTV)
   • Reduces backpropagation depth (memory overhead)
   • Implements early exit layers at different depths
   • Uses ensemble voting from multiple exit points
   • Reduces memory consumption for training
   • Files: utils/trainer_wrappers.py, main.py

3. HARDWARE SCHEDULING STRATEGY
   • Handles irregular computation patterns from LUC and ALTV
   • Optimizes data movement and computation overlap
   • Efficient GPU utilization for pruned/quantized layers
   • Files: scripts/

DIFFERENCES FROM STANDARD FINE-TUNING:
─────────────────────────────────────────────────────────────────────────────
✓ Standard fine-tuning: All layers, full precision → High memory/compute
✓ Edge-LLM approach: Selected layers, mixed precision → Efficient inference

USE CASES:
─────────────────────────────────────────────────────────────────────────────
• Deploy LLMs on mobile phones (4-8GB RAM)
• Edge servers with limited computational resources
• Real-time inference without cloud connectivity
• Privacy-preserving on-device inference
• Reducing operational costs

6. CORE FUNCTIONALITIES
================================================================================

FUNCTIONALITY 1: LAYER-WISE PRUNING
─────────────────────────────────────────────────────────────────────────────

What it does:
    • Removes less important weights layer-by-layer
    • Different pruning ratios for different layers
    • Based on pre-computed MSE (Mean Squared Error) analysis

How it works:
    1. Load model (32 layers)
    2. Analyze which weights are least important (stored in 
       pruning/layer_wise_MSE_results/)
    3. Remove weights progressively
    4. Fine-tune to recover accuracy

Files involved:
    pruning/pruner.py               Main interface
    pruning/llama_pruning.py        Layer iteration
    pruning/sparsegpt.py            SparseGPT algorithm
    pruning/pruning_schedular.py    Schedule management

Results:
    • 50% average sparsity (half weights removed)
    • 30-40% faster inference
    • Minimal accuracy loss (<2%)

Example output:
    Layer 0: 50% pruned
    Layer 1: 48% pruned
    ...
    Layer 31: 52% pruned

────────────────────────────────────────────────────────────────────────────

FUNCTIONALITY 2: LAYER-WISE QUANTIZATION
─────────────────────────────────────────────────────────────────────────────

What it does:
    • Converts 32-bit floats to 8-bit or 4-bit integers
    • Different bit-widths for different layers
    • Quantization-aware training (learns to adapt)

How it works:
    1. Critical layers (embedding, final): keep 8-bit
    2. Normal layers: use 4-bit quantization
    3. Train with fake quantization to adapt weights
    4. Quantize at inference time

Files involved:
    quantization/quantizer.py           Quantization operators
    quantization/quantizedlinear.py    Quantized linear layer
    models/edge_llama_modelling.py      Model with quantization support

Results:
    • 75% memory reduction (32-bit → 4-bit)
    • 2-3x faster inference (with hardware support)
    • <1% accuracy loss

Example configuration:
    layers_qats = {
        2: {"w": 4, "a": 4, "kv": 4},   # Special layer: 4-bit everything
        29: {"w": 4, "a": 4, "kv": 4},  # Special layer: 4-bit everything
        other: {"w": 8, "a": 8, "kv": 8} # Default: 8-bit
    }

────────────────────────────────────────────────────────────────────────────

FUNCTIONALITY 3: ADAPTIVE LAYER TUNING & VOTING
─────────────────────────────────────────────────────────────────────────────

What it does:
    • Uses multiple exit points (early exits)
    • Combines predictions from different layers
    • Reduces memory for backward pass

How it works:
    1. Insert linear classifiers at layers 8, 16, 24, 32
    2. Each can output predictions independently
    3. Ensemble voting combines all predictions
    4. Training only backprops through selected layers

Files involved:
    utils/trainer_wrappers.py       Custom trainer with early exit
    main.py                         Callback for ensemble voting

Results:
    • 60-70% reduction in backward memory
    • Similar accuracy to full backprop
    • Enables training on smaller GPUs

Example:
    Input → Layer 8 (exit layer 1) → Output 1
          → Layer 16 (exit layer 2) → Output 2
          → Layer 24 (exit layer 3) → Output 3
          → Layer 32 (main output) → Output 4
    
    Final = Weighted vote of Output1, 2, 3, 4

────────────────────────────────────────────────────────────────────────────

FUNCTIONALITY 4: PEFT (PARAMETER-EFFICIENT FINE-TUNING)
─────────────────────────────────────────────────────────────────────────────

What it does:
    • Only updates small LoRA adapter matrices
    • Freezes main model weights
    • Reduces trainable parameters by 99%

How it works:
    1. Freeze all 7B model parameters
    2. Add small LoRA modules (rank 8)
    3. Only train LoRA matrices
    4. Merge at inference time (optional)

Results:
    • Only 0.1% of parameters trainable
    • Fits on consumer GPUs (8GB)
    • Adapts model to new tasks
    • Fast deployment (32MB adapter file)

Example:
    Original model: 7,000,000,000 parameters
    Trainable: Only 8,000,000 parameters (LoRA)
    Training memory: 24GB → 8GB possible

What it evaluates:
